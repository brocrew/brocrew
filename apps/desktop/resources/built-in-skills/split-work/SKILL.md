# Divide only where it helps

The result owner keeps the whole requested outcome in view. Divide work when distinct expertise, independent outputs or saved time justify the coordination. Keep tightly dependent steps together. State the handoff boundary before parallelizing: what each helper may change, which version of an input it uses, and which output the owner expects. Work that shares a mutable file, account or device may need sequence or one service rather than independent writers. A research claim needs a usable source, a written result needs the agreed audience and format, and a plan needs assumptions the owner can trace; put those checks in the child brief that produces the relevant output. Name the output and done condition for each child, what it needs from earlier pieces, and who integrates it. A specialist may do a bounded part itself when handoff costs more. Do not pass the same whole job down another layer merely because delegation is allowed.

Choose checks that fit the outcome. Research needs usable sources and honest uncertainty; writing needs its audience and agreed language; planning needs stated assumptions and actions; continuing help needs feedback and a way to resume. These are questions to settle from the request, not fixed deliverables. Independent review is a separate piece only when a distinct judgement or risk calls for it. Add a project lead only when several owners need continuing coordination or dependency management.

For many similar items, give bounded ranges to one reusable helper profile. The owner integrates the ranges and, when warranted, asks a reviewer to check the combined result. Put range names in piece titles, never in profile names. Use a few parallel workers of that profile only when simultaneous work saves real time after coordination; otherwise give pieces in sequence. Workers share profile memory but not live context, so give file-producing pieces separate output locations and keep shared instructions and routine status in project records. Never use parallel work for a service. Do not create a profile per slice.

Avoid competing writers. Before replacing an agent that wrote files, confirm it finished or stopped; withdrawal alone does not stop an active turn. Give the replacement a stable input version and clear ownership of its output. Review a named snapshot and re-check the final corrected version. Keep temporary output apart from deliverables. Use the assigned project location; for new saved work, give the owner the full path before dispatch.

When pieces return, compare them with their briefs, resolve conflicting claims and integrate one result. If a helper's work stalls, inspect that piece and use ask-and-wait; do not duplicate it as a new task. Keep routine findings in files and send only a useful milestone or material change.
