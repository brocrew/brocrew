# Chrome release paths

The active production design is the unsigned repository list described in [plugin-production.md](contracts/plugin-production.md). `scripts/export-chrome-plugin.mjs` prepares the standalone Chrome repository and its private release workflow. Users install from Settings → Plugins; there is no signing-key or terminal step. The older builder and signing recipe below remain dormant tooling for this train.

# Legacy signed-catalogue tooling

Prepare the tooling checkout with its locked dependencies (`pnpm install --frozen-lockfile --ignore-scripts`) and supply a Node 22 installation, including npm. Create an empty output directory, then run `node scripts/chrome-release.mjs --commit <full-reviewed-commit> --output <absolute-empty-folder> --archive-url <https-archive-url> --node <absolute-node22-binary>`. The builder checks out that commit privately, installs the plugin's locked dependencies with scripts disabled and without personal npm configuration, builds the package, runs its fake-browser tests and the app's pure verifier, and writes `chrome.tar`, `plugin.json`, `catalogue.json` and `release-receipt.json`. Test dependencies come from the tooling checkout, whose lockfile must match the reviewed commit. No real browser runs. Review the output and its catalogue SHA-256 before signing; a failed build must be retried in a fresh empty output directory.

After reviewing the catalogue, run `python3 scripts/sign-plugin-catalogue.py --catalogue <output-folder>/catalogue.json --expected-sha256 <reviewed-sha256> --public-key <public-key.pem>` in a terminal. The helper uses the encrypted key already held at `~/.brocrew-signing/catalogue.pem` and Homebrew's `/opt/homebrew/bin/openssl`; it does not create a key. The key must be an owned regular file with mode 0600, inside an owned folder with mode 0700; links anywhere in its path are refused. If using `--key`, supply its absolute path. Enter the key's passphrase at the hidden prompt. The helper checks the reviewed hash before prompting, signs the exact catalogue bytes with Ed25519, verifies with the supplied public key, and creates the raw 64-byte `catalogue.sig` beside the catalogue. It prints `signed and verified` only after verification succeeds. Keep the key and passphrase private; neither belongs in a command argument, repository, log or release upload. An existing signature is preserved. To use a different local installation, `--key` and `--openssl` take explicit paths; the tests use these options solely with temporary keys.
