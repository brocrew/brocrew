# Generic plugin tool forwarding

`createPluginToolBroker` forwards MCP for one running plugin instance. The process runner owns and retains its MCP client. The broker neither reconnects nor closes that client after a call; process stop owns connection cleanup.

`listTools(workspaceId)` follows the running server's inventory pagination and returns its definitions. The app has no tool-name table, profile decoder, resource claims or per-agent tool grants. Tool arguments, schemas and domain settings belong to the plugin. A newly installed package can change its tools and schemas without changing app code.

`callTool({workspaceId,requestId,name,arguments,origin,meta?,signal?})` forwards arguments unchanged. Workspace, request and origin are MCP `_meta` fields outside arguments. The result keeps MCP content blocks, structured content, `isError` and metadata. A tool result with `isError: true` remains a result. Remote MCP protocol errors retain their code, message and data through controller and provider calls. SDK MCP errors retain their details even at codes also used for local close/timeout events; a numeric code alone does not establish origin. Ordinary local non-MCP connection failures are separate transport rejections. Local diagnostics retain fixed reason words; remote error messages/data, raw exceptions, arguments and results are not diagnostic fields. The app never retries a dispatched tool automatically.

The workspace switch and actual instance lifetime gate forwarding. Turning a workspace off stops new calls and suppresses late app effects in that workspace; another enabled workspace remains usable. `invalidate()` retires that broker instance. Callback callers retain `{pluginId,workspaceId,instanceId}` so an old callback cannot select the replacement installed instance.

Calls can overlap. Cancellation aborts only the matching workspace/request and forwards MCP cancellation through the retained SDK client. It is best effort: an external operation may already have acted. `cancelTool` reports that cancellation was requested; `completed: false` means no positive downstream completion receipt is supplied. Cancellation does not promise rollback or physical quiescence, does not close the instance client and does not disable future calls. The host adds no call queue, one-active-call policy, proof deadline or recovery quota.

The supervisor's lifecycle bridge uses this same broker for provider routes and app callbacks. The loopback provider adapter changes names only when provider syntax requires it and reverses them before dispatch. The SDK handles MCP framing and protocol validation; the app adds no domain precondition or postcondition.

Focused tests cover paginated unknown tools, exact results and metadata, overlapping calls, cancellation isolation, workspace switches, retained clients, changed schemas and stale-instance callbacks. They use fictional MCP servers and loopback provider endpoints. Real provider sessions, packaged applications, native process qualification and account flows remain separate checks.
